System design before implementation
Data shape: one versioned publication per UUID, bound to a portal. Text variants carry content; deliverable variants carry the exact file version. Draft/published visibility is independent of the private/shared file lifecycle.
Recover the three retained verbs. Reuse partner deliverable authorization and the standard idempotency envelope. Replace the existing server projection, consumed by both password/session client readers and partner preview. Leave password and URL code untouched.
Alternative: separate v2 read endpoint with a duplicate projection. Rejected because client session reads and partner preview could diverge. Chosen: one bounded SQL projection and one authoring module, no cache, queue or external service. One indexed portal read plus bounded aggregates, at most 100 publications, 1000 authored rows. At 10x load portal writes serialize only per portal; database connections break first. Fail closed on missing/disabled/inaccessible portal and stale/private/unfinalized/foreign files. No N+1, async work, fan-out or external retry. Database transaction rollback handles failures; no external circuit breaker applies.
