# Partner document intake

Size is medium. One owner changes the reservation module, transport, registry and contracts. No app or factory runtime changes.

The data shape is an existing ops.deal_deliverable reservation with immutable destination derived from its server-owned object_key namespace. Deliverables retain deliverables/. Document reservations use document-intakes/. Both bind tenant, deal and reservation UUID. Document attachment UUID equals reservation UUID. Neither keys nor credentials are accepted from the app.

Design A adds target_collection to the existing reservation, transport and finalization. The namespace persists the destination without DDL. Design B adds independent document verbs and reservation storage, duplicating quotas, byte verification and retry machinery. Choose A. Existing calls default to deliverables. New calls select documents. The document receipt has its own deal-document-intake.v1 contract; deal-documents.v1 stays unchanged.

System design. Reserve, upload and finalize are sequential. SQL owns authority, metadata and receipt. R2 owns immutable bytes. One upload is bounded to 25 MiB; the existing deal quota is 100 reservations and 500 MiB across destinations. At 10x traffic, R2 concurrency or the per-deal advisory lock is first contention. No fan-out, queue or N+1 reads. No metadata cache; all authority and receipts use current SQL. Attachment insertion and reservation finalization commit together, so a failed transaction exposes neither. A failed R2 put leaves a retryable started reservation through rollback; late puts hold only identical private bytes. Hash or MIME failures leave no attachment. Abandon and expiry refuse finalization and never delete immutable keys during concurrent writes. Abandonment persists the existing terminal expired lifecycle state and releases file and byte quota immediately, including verified reservations. The receipt remains expired. Immutable private bytes are retained; their cleanup is outside this contract. Replayed abandonment leaves state unchanged and releases no additional quota. Natural expiry of unuploaded reservations releases quota on the next reserve. No automatic retries. Existing transport caps 60 requests per minute per partner per isolate, four outstanding storage operations, ten-second deadlines, and a storage breaker after three failures for thirty seconds with a structured alert. These are isolate-local limits, not a global rate-limit guarantee. SQL calls use existing transaction deadlines. Every write uses the existing principal-bound idempotency envelope. Replaying reserve with the original key retrieves its original reservation after a lost response. Finalize replay or current receipt GET returns the same attachment identity. Changing any reservation field with the same key is refused by the envelope. No live production reads in this worker.

Throughput checkpoint. Blocking first steps are grounding and lifecycle tests. Transport and storage are coupled and remain with one owner. Shared mutable state is one row locked by upload/finalize/abandon; per-deal reservation uses the existing advisory lock. Smallest safe decomposition is one contract PR, then a separately pinned app consumer.

Never rules. A document appears only after verified bytes and atomic finalize. A retry never creates a second attachment. A non-visible deal or inactive session never receives bytes or receipts. Abandoned or expired reservations cannot finalize. A document never enters the deliverables publication list.

Transition coverage. The registered PostgreSQL suite is mcp-server/test/deal-document-intake-postgres.test.mjs. The test named reserve replay, photo upload, atomic attachment finalize and document readback covers reserve, uploading, verified, filed, repeat finalize, receipt, lost reserve and invalid discard after filing. The upload failure test covers failed upload returning to reserved and refused early finalize. The finalize failure test covers SQL failure, recovery, transport auth and discard. The abandon test covers both discard origins, repeated discard, both expiry origins and refusal after expiry. Existing deliverables suites cover bounded-body timeout, storage failure and session revocation during upload. The transient uploading state is inside the row-locked transaction and failures roll it back.

This is one reservation with abstract verification/storage outcomes, authorization revocation, and transactional rollback; it does not model byte contents, clocks, multi-reservation quota arithmetic or external storage internals. The explicit model replaces that unverified generated skeleton.

Round-one root cause. The old abandon handler only shortened expires_at. Quota counts stored state, so a verified row stayed charged forever. The corrected handler uses the schema's existing expired terminal state; adding a distinct abandoned enum would require a migration and change the receipt contract without adding behavior. Compare-and-set under the existing row lock makes same-key and fresh-key discard replays idempotent. No new interface, storage, timers or compensating counter is needed. The registered regression fills file and byte quotas separately, verifies a real upload, abandons it, reserves exactly one replacement, replays discard with both keys, and requires another reserve to fail. The deadline remains in the future, proving quota release is state based.

Blast radius. Both destinations share boundedBody, verifyDeliverableBytes, current-session checks and quotas. The safety fact is that document attachment insert and finalized state share one transaction after verified state. The failure-injection test proves no attachment survives a failed finalize and a retry returns one identity. Existing default deliverables tests prove private/shared lifecycle and downloads still work. Documents cannot be marked shared or returned by list-deal-deliverables.
