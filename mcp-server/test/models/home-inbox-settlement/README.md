# Home inbox settlement model

The v3 read derives automatic settlement from canonical task completion, sent replies, resolved fact reviews and received tour feedback. It preserves v1 and v2 and their opaque command versions. Reads write no domain rows or dispositions.

The model separates canonical work, manual disposition and explicit Undo. The numbered PostgreSQL cases execute the work lifecycle through registered verbs. The named adapter statechart matrix exercises every feasible adapter edge, including resolution while snoozed, manually settled and explicitly returned to Inbox. Fact review resolves through its registered canonical command; tour feedback arrives as an event for the exact grant. Each matrix case rolls back its synthetic fixture and checks repeated reads before and after the transition. The chart has 20 visible arrows. The statechart summary records 28 model states and 83 distinct non-stuttering state pairs. TLC reports 120 generated states including three initial states. The graph has 89 named action edges between distinct states and 28 Stay loops. The transition matrices cover all 89 named edges. ResolvedOnly, OverrideWins, SnoozeWins and NoDeadlock hold.

The model excludes networking, actors, stale writes, truncation and source storage. Separate PostgreSQL tests cover replay, actors, stale writes and bounds. Reopen applies only to work and fact reviews, including after explicit Undo. New evidence reopens a fact review. Tour feedback is append-only for a share grant, so the model excludes same-item Reopen for that adapter. Manual settlement remains a separate choice.

Replacing v2 would break its deployed app parser. The v2 and v3 SQL reads share one disposition placement function. The v3 read transforms the actor-scoped v3 snapshot and retains its command authority. The app must pin v3 and hydrate command receipts through v3. The auto_settled field grants no command authority.

Completion notifications and call-processing completion do not prove all partner work resolved. Fact review uses the canonical pending predicate, including new observations and extraction abstentions. Tour feedback means receipt of a client shortlist or comment for the exact share grant, as AC-INBOX specifies. It does not claim that a broker has acted on the feedback. The adapter tests execute both named resolution transitions, Undo, replay, snooze, stale versions and actor isolation. The app still consumes v2, so this producer change alone changes no deployed app behavior.
