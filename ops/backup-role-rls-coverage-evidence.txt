WR-000044 / decision 11376c54 — backup RLS fix: reproducible safety evidence
============================================================================

WHAT THIS IS. A captured run of ops/backup-role-rls-coverage-selftest.py with
CARR_LOCAL_PG_DSN set to a disposable PostgreSQL 17 cluster, committed so a
reviewer who cannot stand up Postgres can see the numbers, and so anyone can
re-run it and reproduce the INVARIANTS (the absolute digests below are
environment-specific — a disposable cluster holds fewer objects than production
— but the invariance, the contrast, the refusal, and the row parity are
deterministic).

The proof lives in the *-selftest.py (not a *-local-pg-acceptance.py) on purpose:
a selftest is excluded from the SCAC script-entrypoint census
(ops/scac-mutation-inventory.mjs isScriptEntrypoint), so this proof harness adds
nothing to the sealed mutation registry and needs no reseal. Without a DSN the
same file runs only the source contract (and passes) in ci.sh.

HOW TO REPRODUCE (LC_ALL=C, disposable cluster, never port 55432):
  1. initdb a throwaway PG17 cluster as superuser carr_ci; create role neondb_owner.
  2. Create db carr_proof; load db/schema.sql; DATABASE_URL=...carr_proof \
       .venv/bin/python tools/migrate.py --apply --yes    # applies through 0475
  3. CARR_LOCAL_PG_DSN=...carr_proof \
       .venv/bin/python ops/backup-role-rls-coverage-selftest.py
The selftest creates carr_backup (mirroring migration 0119) because
db/schema.sql deliberately omits it — that omission was the original false-green.

THE PROOF, IN TWO HALVES (both required):
  * INVARIANCE — the FULL sealed SCAC v10 census 4th block (roles + memberships
    + ownership_rows, migration 0471's count=52 / sha256:345871 block, copied
    verbatim) is byte-identical before and after migration 0475's policy.
  * CONTRAST  — on the SAME cluster, ALTER ROLE carr_backup BYPASSRLS moves that
    same block's digest; ALTER ROLE ... NOBYPASSRLS returns it. So the census is
    bypass-sensitive but policy-insensitive: the policy path is safe precisely
    where the naive BYPASSRLS path was not.
