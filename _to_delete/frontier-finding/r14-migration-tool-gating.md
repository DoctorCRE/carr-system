# R14 — How established migration tools model gated/skipped sets (researched 2026-09-01)
Flyway (the richest precedent): baseline = ordinal cut line writing a tagged history row; skipExecutingMigrations = ledger row WITHOUT executing SQL (Teams); cherryPick = explicit named set, everything else marked ignored in history. Lesson: separate (a) which files are exempt (named set), (b) every skip still writes a first-class ledger row, (c) ordinal cut vs named subset. No tool ships "skip exactly this named+digest-verified set" - the custom gap.
Alembic: stamp writes the version row with no execution, no digest check, no reason, no audit - documented as emergency resync, observed normalizing into routine unstick moves. THE anti-pattern.
Sqitch: no skip primitive at all; the plan file IS the ledger - deviations must be first-class, permanent, diffable source entities.
Atlas: --baseline marks applied-without-executing per environment config; its own docs warn misaligned baselines create "dangerous schema drift... difficult to recover" - no digest verification exists. Static author-time config, no runtime activation probe.
dbmate/goose: no primitive; goose issue #431 requests exactly a named blacklist (not an ordinal baseline) - independent demand for the named-set shape.
Three warnings (convergent): (1) baselines are unchecked assertions unless digest-verified - drift is a documented hazard; (2) an unaudited break-glass pointer move becomes the path of least resistance and normalizes; (3) open-ended conditional/env-branching mechanisms generalize past their justification - the register must be CLOSED and enumerable (exact filenames + digests), never a predicate that could match unreviewed future migrations.
