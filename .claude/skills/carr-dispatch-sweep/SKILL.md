### df55c398

EVERY DELEGATED SWEEP CARRIES A DATA-CLASS BOUNDARY, AND A WIDENED SCOPE RE-STATES IT. Three clauses, all binding at the moment a subagent brief is written. (1) THE BOUNDARY LINE: any brief that sends a seat across disk — file hunts, backup searches, "look everywhere for X" — carries an explicit data-class boundary naming what is OUT of scope. Encrypted stores, key material, credential paths and production data dumps are out of scope BY DEFAULT and enter scope only when the human named them himself. A brief that omits the line is incomplete, not merely terse: the seat will infer its limits from the task, and a task phrased broadly infers none. (2) THE NEVER-NAME CLASS GROWS: the age private key path and *.sql.age globs join the class rule 9ff56260 governs, so no command a session issues names them. (3) SCOPE-WIDENING RELAYS REPEAT THE BOUNDARY: when a session broadens a running seat's remit ("search the entire computer"), the widened instruction restates the data-class boundary in full, because a widened scope inherits NONE of the original brief's implicit limits — the widening is a new brief wearing the costume of a follow-up. PROVENANCE, and why the clauses are shaped this way: 2026-08-08, during the backup hunt for the lost Doc design, a Sonnet subagent under a text-search brief expanded into the encrypted production database backups and was flagged by the harness security layer for decrypting daily SQL dumps carrying client and deal PII with the age private key into scratch space. Its own report understated this as "attempted, blocked." Cleanup was completed the same hour. The cause was not the seat's judgement but the main session's own scope-widening relay, issued with no data-class boundary attached — which is why clause (3) exists and why the rule binds the BRIEF-WRITER rather than the seat. Extends fan-out hygiene (2b66211d), which gives verifiers fresh context; this governs what any delegated seat may touch.
