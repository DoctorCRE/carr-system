### e65efc68

WRITE THE TEST BEFORE THE THING, AND ESPECIALLY BEFORE A GATE. On any non-trivial build, the check is WRITTEN and RUNNING before the implementation is finished — not designed in advance and written afterwards. This is the missing half of rule 43e2ef76 (plan the check before you build the thing): planning a check and writing it are different acts, and the gap between them is where defects live. Red, then green, then refactor.

THE BAR IS HIGHEST FOR ANYTHING THAT GATES OTHER WORK. A promotion gate, a hook, a linter, a CI script, a validator — anything whose job is to say yes or no about other code — gets its own selftest, and gets it FIRST. Every other gate in carr-system has one; the reason this rule exists is that ops/ci.sh shipped without one.

THE COST, measured 2026-08-13 rather than argued. ops/ci.sh collected FIVE defects in a single afternoon, every one found by running it: (1) ${STRICT:+--strict} expanded on STRICT=0, because :+ fires on any non-empty value and "0" is non-empty; (2) declare -A is bash 4 and macOS ships 3.2.57; (3) core.fileMode is false in this repo so chmod never reached the index, and CI died with exit 126; (4) a known-gap mechanism that suppressed the loopback SAFETY refusal along with the failure it was meant to excuse, which would have let a database DSN pointed at production pass silently; and (5) the worst — under zsh the class loop does not word-split, so all eight checks skipped and the script still printed "CI passed, every class green". Eight green, zero executed, caught by a peer session rather than by me.

WHY (5) IS THE ARGUMENT. Defects that make a gate FAIL are survivable; someone notices. A defect that makes a gate SUCCEED FALSELY converts unverified into verified silently, and every downstream claim inherits it. That failure mode is only reachable by a test, because by construction nothing else is looking. The selftest written afterwards caught (4) within a minute of existing.

Composes with 2b66211d (verifiers get fresh context) downstream and 43e2ef76 upstream: 43e2ef76 fixes the success criteria while they can still be wrong, this rule makes them executable before the implementation can drift, and 2b66211d has someone else run them.
