### ede4c735

WRITING-RULES BINDS PROSPECT-VISIBLE SURFACES ONLY; INTERNAL TEXT IS EXEMPT. DNA/writing-rules.md governs anything a prospect could ever see — outreach, social, proposals, packets, marketing HTML, artifacts, diagrams. It does NOT govern internal-only text: agent prompts and job descriptions, migration comments, specs, work orders, session notes, code comments and reports that never leave the system. The reason is that precision in an instruction beats voice compliance in text no client reads, and linting internals spends attention on surfaces with no audience. The linter stays a hard gate on client-facing drafts (`run.sh lint <file> --surface email|social|proposal|web`) and is not run against internals. Boundary case, decided the same day: an agent refused the instruction "this is a generic pressure-test, not a read on this person" because "X, not Y" is the banned compressed contrast-reframe, and rewrote it. Its rewrite was kept because it was cleaner, but the refusal itself was over-application — that line lives inside an agent prompt, which is internal.
