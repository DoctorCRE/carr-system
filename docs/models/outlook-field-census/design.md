Intake writes it atomically while its private snapshot exists. The public binding contains only a random generation ID, operational revisions and timestamps; private source and sidecar manifest digests and mailbox binding are folded into a one-way generation commitment, never printed individually.
One pass over admitted rows and one streaming pass over copied files scale from 1,167 to 11,670 rows. File hashing is the first capacity limit. No remote calls, queues, acquisition or filling changes apply. Existing unchanged-store caching requires the current census schema, so installation obtains a first census on the next natural run. Intake serializes publication with its existing lock; readers read one file. A failed write leaves the previous whole bundle, which a read-only verifier rejects when older than its required observation floor. Population reconciliation uses the existing receipt admission-exclusion counters. Unadmitted equals outside-account plus ambiguous plus unresolved rows. Rejected equals decoder_rejected. Decoded equals admitted plus unadmitted, and observed equals decoded plus rejected. Stored rows plus unknown-account rows cannot exceed decoded rows. Stored ambiguous and unresolved causes cannot exceed their corresponding exclusion populations. The CLI refuses disagreement across sections, even when each section reconciles internally.
