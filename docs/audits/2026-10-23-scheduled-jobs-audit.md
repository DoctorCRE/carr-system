These comprise 27 canonical launchd files, 14 headless files, and nine tool-local templates; eight labels have duplicate templates. These counts are not additive execution counts: native/headless ownership overlaps and duplicate plist sources are reconciled below.

GitHub and Worker cron are UTC. Chicago is UTC−5 on this date and UTC−6 in winter. Monthly day-range firings are intentional catch-up windows where a completion gate is present.
- The two current failures are **user-reported symptoms**, not reproduced live. Source proves the failure paths and corrective design; it cannot identify the installed credential's condition or why a particular remote request took over 30 seconds.
- `AGENTS.md` was read first. The user's explicit Markdown destination, report-only scope, draft-PR endpoint, and ban on live CARR/production take precedence over generic repository instructions to store findings through live verbs, publish board updates, or merge delivery. No live CARR/production service, scheduler, backup, credential store, keychain, environment dump, or DB dump was accessed. ## Findings ranked by impact on Joe's daily use

### 1. Progress-board publication times out before answer polling and Joe's local action list refresh — high

**Subject:** `local.carr-progress-board`, reported 30-second timeouts. The plist runs every five minutes and at load ([ops/launchd/local.carr-progress-board.plist:20](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/ops/launchd/local.carr-progress-board.plist#L20), [ops/launchd/local.carr-progress-board.plist:26](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/ops/launchd/local.carr-progress-board.plist#L26)); the wrapper selects the canonical repository interpreter and invokes `render carr-v5 --publish` ([ops/progress-board-render.sh:13](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/ops/progress-board-render.sh#L13)).

**Root cause proven by source:** every board record call overrides the shared transport's 120-second default with a fixed **30-second outer subprocess timeout** ([tools/progress_board.py:2010](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/progress_board.py#L2010), [tools/progress_board.py:2014](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/progress_board.py#L2014); [lib/record_call.py:86](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/lib/record_call.py#L86), [lib/record_call.py:102](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/lib/record_call.py#L102)). Timeout becomes `transient: timed out after 30s` and the board raises immediately ([lib/record_call.py:104](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/lib/record_call.py#L104); [tools/progress_board.py:2016](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/progress_board.py#L2016)). The actual call chain is shell → Python wrapper → Node HTTPS client ([run.sh:78](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/run.sh#L78), [run.sh:100](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/run.sh#L100); [tools/call-verb.py:166](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/call-verb.py#L166)); the Node `fetch` has no application deadline/abort signal ([mcp-server/local-verb.mjs:203](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/mcp-server/local-verb.mjs#L203)). Killing the wrapper does not establish cancellation of the remote effect or every descendant. Sequential read/write/readback calls and page publication increase exposure ([tools/progress_board.py:2267](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/progress_board.py#L2267), [tools/progress_board.py:2463](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/progress_board.py#L2463)). The scheduled GitHub GraphQL path uses **60 seconds**, so attributing this specific 30-second record-call diagnostic to the old per-PR GitHub reader is incorrect ([tools/progress_board.py:785](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/progress_board.py#L785)). Without the full supplied log, another historical checkout remains possible; remote latency, host networking and current deployed state were not tested.

**Consequence and visibility:** a failed `carr-v5` publication skips answer polling and `publish_needs_joe_local`; all-repos publication is still attempted, and the original failure is rethrown ([tools/progress_board.py:2776](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/progress_board.py#L2776)). Joe can see stale cards/questions and delayed action-list updates. A loaded job's nonzero exit can reach the local watchdog's next prompt digest, not a direct notification; the needs-Joe page independently becomes stale after two hours ([tools/progress_board.py:2796](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/progress_board.py#L2796)). Local notes remain durable.

**Concrete fix:** give record transport one explicit end-to-end deadline, abort HTTP at that deadline, and reap the full subprocess group. Carry verb/board/phase/elapsed-time diagnostics without payloads or secrets. Select the publication budget from measured request duration; merely increasing 30 is not evidence of a fix. After a timeout, reconcile the idempotent write with readback before retrying, preserving the same key and version. Make answer polling and needs-Joe refresh independent bounded stages so a legacy board failure cannot suppress them. Preserve last verified snapshots and mark freshness explicitly. **Effort: 1–2 days.** Acceptance: injected slow read, ambiguous completed write and failed legacy publish produce bounded termination, no duplicate mutation, visible stale status, and independently attempted answer/list refresh. The underlying host/provider delay requires a later authorized operational observation.

### 2. Recording capture and consent can report success after failure — high

**Evidence:** capture claim and polling catch record-service exceptions and turn them into empty/no-work success ([tools/dictation-rig/bin/capture-bridge.py:260](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/dictation-rig/bin/capture-bridge.py#L260), [tools/dictation-rig/bin/capture-bridge.py:491](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/dictation-rig/bin/capture-bridge.py#L491)); shell polling also ends successfully ([tools/dictation-rig/bin/capture-poll.sh:69](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/dictation-rig/bin/capture-poll.sh#L69)). Consent announcement playback/marker helpers return failure, but their caller ignores it and exits zero ([tools/dictation-rig/bin/consent-watch.sh:66](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/dictation-rig/bin/consent-watch.sh#L66), [tools/dictation-rig/bin/consent-watch.sh:192](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/dictation-rig/bin/consent-watch.sh#L192)). The scheduled wrapper records the child's exit, so a zero becomes a successful heartbeat ([bin/run-scheduled.sh:76](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/bin/run-scheduled.sh#L76)).

**Consequence and visibility:** meetings/voice captures can stop reaching the product while recent success receipts reassure freshness checks. Errors remain in local logs; a nonzero-exit watchdog cannot distinguish this from an empty queue. Capture-watch claims new sessions; capture-poll completes already-claimed sessions. Both are needed; polling does not recover an unclaimed recording.

**Concrete fix:** return a typed distinction between verified empty queue and unavailable/auth-refused queue; propagate unavailable as nonzero while retaining files and deduplication. Aggregate playback/marker errors while continuing other sessions. Keep failed claims retryable before the 24-hour backlog cutoff ([tools/dictation-rig/bin/capture-watch.sh:46](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/tools/dictation-rig/bin/capture-watch.sh#L46)). Record last verified intake/poll success separately from process invocation. **Effort: 1–2 days.** Acceptance: empty queue succeeds; auth/network/playback failure produces failed receipts; timed jobs reach the digest, while event-only capture requires the coverage fix in finding 4. Existing captured files remain retryable without duplicate ingest.

Acceptance includes absent enabled job, dead scanner, fresh failed receipt, intentionally disabled job, and recorder outage/recovery without duplicate receipts.

**Evidence:** nightly accumulates `NIGHTLY_RC` but both export and main paths exit zero ([bin/nightly.sh:64](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/bin/nightly.sh#L64), [bin/nightly.sh:84](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/bin/nightly.sh#L84), [bin/nightly.sh:107](https://github.com/DoctorCRE/carr-system/blob/3c948ed92de0d4344d54ab8b17dc170363ab187f/bin/nightly.sh#L107)). For checkout refresh, verify the canonical checkout and `main`, fetch and fast-forward only `origin/main`, refuse dirty/unexpected branches, and fail the aggregate if any repo did not refresh. **Effort: 0.5–1 day per independently shippable change.** Acceptance: one injected failed stage/repo remains visible in both detailed receipts and top-level status; successful siblings still complete.
