System design before code. Size L. One worker, no delegation.
Data shape: immutable derivative keyed by attachment UUID, original SHA256 and text-format version; deal UUID bound on every read/write. Pages are exact deterministic text_pages strings. Lines are LF-delimited, numbered from one; long lines are returned as bounded character-offset fragments without losing text.
A: Postgres JSON pages in one row, single transactional binding and write, bounded to 500000 Unicode characters/1000 pages. B: immutable R2 JSON plus Postgres locator; smaller database but two-resource publication, orphan cleanup and an extra read failure. Pick A for bounded data and transactional consistency.
Interface: record-deal-document-text automation-only; list-deal-document-text-sources automation-only keyset source scan; read-deal-document-text authenticated read, deal/document UUID and optional pinned original hash, page/line/offset position. New hash without pinned hash starts a fresh view; pinned old hash refuses source_changed.
Current live attachment count is deliberately unobserved because production calls are forbidden. Capacity formula at N attachments: <=2 MB raw UTF8 pages per derivative + JSON overhead; 10N <=20N MB. No guessed current count. Backfill dry run emits observed eligible and missing counts for coordinator sizing. Indexed lookup O(log N), one database read per viewport, no N+1 or application cache. First limit is database storage for historical hash versions. Retain superseded versions, never serve them for current content.
Availability: parser/R2 failure leaves absent for retry; unsupported or empty text produces explicit no_text; database failure aborts and retries by immutable key. Writer rejects stale hashes and changed replay bodies. No model call in derivative producer/backfill/read. Existing extraction model behavior remains untouched.
Async: existing extraction worker produces before model work; backfill serial, capped 10000 sources per invocation and source pages of 100. No new queue, cache, fanout or external API. R2 subprocess deadline 120s; parser 60s; stop batch after first infrastructure error. DB calls use existing record transport timeouts; no retry loops. Idempotency is attachment/hash/format. No stale reads.
Lifecycle is docs/contracts/deal-document-text.v1/lifecycle.mmd, written before implementation. All deletion states converge through attachment deleted_at read guards. Supersession is derived from mismatch with current attachment hash, not a mutable status.
Throughput checkpoint: storage and producer are critical path; contract and backfill use the same derivative shape. One worker prevents registry sharing. Production proof is separate coordinator-owned post-deploy/backfill unit.
